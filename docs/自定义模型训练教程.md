## 整个训练流程

你需要完成下面 7 件事：

1. 安装 Python 环境和 Ultralytics。
2. 收集并标注图片。
3. 把图片和标签分成训练集、验证集和测试集。
4. 创建 `dataset.yaml`，告诉 YOLO 数据在哪里。
5. 先进行一次小规模训练，检查数据是否正确。
6. 进行正式训练，得到 `best.pt`。
7. 评估指标，并用 `test.py` 查看实际检测效果。

## 第 2 步：理解目标检测数据

目标检测的每张训练图片需要包含两部分：

- 原始图片，例如 `0001.jpg`。
- 该图片中每个目标的类别和矩形框，保存在同名文本文件 `0001.txt` 中。

### 2.1 先确定类别

开始标注前，先写清楚自己要检测的类别。例如：

| 类别编号 | 类别名称 | 标注规则 |
| --- | --- | --- |
| `0` | `person` | 框住可见的完整人体，遮挡严重时也保持统一规则 |
| `1` | `helmet` | 只框安全帽，不包含头部或身体 |

类别编号必须从 `0` 开始且连续。一旦开始标注，不要中途改变编号或标注规则。

### 2.2 YOLO 标签格式

每个目标占标签文件中的一行：

```text
class_id x_center y_center width height
```

例如 `0001.txt` 中有两行，表示图片中有两个目标：

```text
0 0.512 0.463 0.210 0.375
1 0.731 0.542 0.125 0.198
```

后四个数不是像素坐标，而是除以图片宽高后的归一化数值，范围必须是 `0～1`。

如果原始矩形框是 `(xmin, ymin, xmax, ymax)`，图片宽高是 `(image_width, image_height)`，转换公式是：

```text
x_center = ((xmin + xmax) / 2) / image_width
y_center = ((ymin + ymax) / 2) / image_height
width    = (xmax - xmin) / image_width
height   = (ymax - ymin) / image_height
```

通常标注工具可以直接导出 YOLO 格式，不需要手工计算。

### 2.3 没有目标的图片

没有任何目标的图片是“负样本”。负样本可以保留，它能帮助模型减少误检。对应的 `.txt` 标签文件可以是空文件。

## 第 3 步：整理数据集目录

建议把数据集放在代码仓库外，避免误提交大量图片。本教程统一使用：

```text
/home/zros/EmbodyAI/Yolo_test/datasets/my_dataset
```

完整目录结构：

```text
/home/zros/EmbodyAI/Yolo_test/datasets/my_dataset/
├── images/
│   ├── train/
│   ├── val/
│   └── test/
└── labels/
    ├── train/
    ├── val/
    └── test/
```

可以先创建空目录：

```bash
mkdir -p /home/zros/EmbodyAI/Yolo_test/datasets/my_dataset/images/{train,val,test}
mkdir -p /home/zros/EmbodyAI/Yolo_test/datasets/my_dataset/labels/{train,val,test}
```

然后把已经标注好的图片和标签分别放进对应目录。

### 3.1 图片和标签必须同名

正确：

```text
images/train/0001.jpg
labels/train/0001.txt
```

错误：

```text
images/train/photo_0001.jpg
labels/train/label_0001.txt
```

图片扩展名可以是 `.jpg`、`.jpeg` 或 `.png`，标签扩展名必须是 `.txt`。

### 3.2 划分训练集、验证集和测试集

常用比例：

- 训练集 `train`：70%～80%，用于更新模型参数。
- 验证集 `val`：10%～20%，用于训练过程中选择 `best.pt`。
- 测试集 `test`：10%～20%，用于训练完成后的最终评估。

不要把同一张图片复制到不同集合中。如果数据来自视频，同一段视频的相邻帧非常相似，应按视频或场景划分，不要把
相邻帧随机分到 `train` 和 `val`，否则评估结果会虚高。

## 第 4 步：创建 `dataset.yaml`

`dataset.yaml` 的作用是告诉 YOLO：

- 数据集根目录在哪里。
- 训练、验证和测试图片在哪里。
- 数据集有哪些类别。

在项目根目录创建：

```text
/home/zros/EmbodyAI/Yolo_test/ultralytics-custom-model-training/dataset.yaml
```

文件内容：

```yaml
path: /home/zros/EmbodyAI/Yolo_test/datasets/my_dataset
train: images/train
val: images/val
test: images/test

names:
  0: person
  1: helmet
```

需要根据自己的数据修改两处：

1. 把 `path` 改成真实数据集路径。
2. 把 `names` 改成真实类别。

例如只检测猫和狗：

```yaml
names:
  0: cat
  1: dog
```

请确保：

- `names` 中的编号从 `0` 开始。
- 编号中间没有跳过。
- 标签中的最大类别编号小于类别总数。
- `train` 和 `val` 必须存在。如果没有测试集，可以删掉 `test` 这一行。

## 第 5 步：先做小规模训练检查

不要一开始就训练几百个周期。先训练 1 个周期，目的是检查环境、数据路径和标签格式。

### 有 NVIDIA GPU

```bash
yolo detect train model=yolo26n.pt data=dataset.yaml epochs=1 imgsz=640 batch=4 device=0 workers=4
```

### 只有 CPU

```bash
yolo detect train model=yolo26n.pt data=dataset.yaml epochs=1 imgsz=640 batch=2 device=cpu workers=2
```

第一次使用 `yolo26n.pt` 时，程序会自动下载预训练权重。

正常情况下，你应该看到：

1. 程序读取 `dataset.yaml`。
2. 扫描训练集和验证集标签。
3. 输出类别数和图片数。
4. 开始第 1 个 epoch。
5. 在训练后进行一次验证。
6. 在 `runs/detect/train/` 中生成结果。

检查训练生成的标签预览图，例如 `train_batch0.jpg`。图中的类别和矩形框应该正确落在目标上。如果矩形框偏移、过大或
过小，不要继续正式训练，应先修正标签格式。

## 第 6 步：正式训练

小规模检查没有问题后，开始正式训练。

### 6.1 推荐的起步命令

GPU 训练：

```bash
yolo detect train \
    model=yolo26n.pt \
    data=dataset.yaml \
    epochs=100 \
    imgsz=640 \
    batch=16 \
    device=0 \
    workers=8 \
    project=runs/my_dataset \
    name=yolo26n
```

CPU 训练：

```bash
yolo detect train \
    model=yolo26n.pt \
    data=dataset.yaml \
    epochs=100 \
    imgsz=640 \
    batch=4 \
    device=cpu \
    workers=2 \
    project=runs/my_dataset \
    name=yolo26n
```

由于命令中指定了 `project` 和 `name`，结果会固定保存到：

```text
runs/my_dataset/yolo26n/
```

如果同名目录已存在，新的训练可能保存到 `yolo26n2`、`yolo26n3` 等目录，因此运行后要留意终端最后打印的保存路径。

### 6.2 训练参数是什么

| 参数 | 作用 | 如何选择 |
| --- | --- | --- |
| `model` | 初始模型权重 | 初学者优先用 `yolo26n.pt` |
| `data` | 数据集配置 | 使用自己创建的 `dataset.yaml` |
| `epochs` | 完整遍历训练集的次数 | 可以先从 `100` 开始 |
| `imgsz` | 训练输入尺寸 | 常用 `640`，小目标多时可适当增大 |
| `batch` | 每批处理的图片数 | 显存不足时减小，例如从 `16` 改为 `8` 或 `4` |
| `device` | 计算设备 | `0` 是第一张 GPU，`cpu` 是 CPU |
| `workers` | 并行加载数据的进程数 | 加载数据报错时可改为 `0` |
| `project` | 训练结果根目录 | 用项目名命名，方便管理实验 |
| `name` | 本次实验名称 | 可写模型和数据版本，例如 `yolo26n_v1` |

### 6.3 选择哪个模型

- `yolo26n.pt`：最小、最快，适合初次实验和资源有限的设备。
- `yolo26s.pt`：比 `n` 更大，通常有更高的准确率，但训练和推理更慢。
- `yolo26m.pt`、`yolo26l.pt`、`yolo26x.pt`：逐渐增大，需要更多显存和计算时间。

先用 `yolo26n.pt` 确认数据和训练流程最稳妥。只有当数据质量没有明显问题，且小模型精度仍不够时，再尝试更大模型。

### 6.4 使用 Python 代码训练

命令行和 Python 接口的效果相同。如果你希望在自己的 Python 项目中启动训练，可以创建 `train.py`：

```python
from ultralytics import YOLO

model = YOLO("yolo26n.pt")
model.train(
    data="dataset.yaml",
    epochs=100,
    imgsz=640,
    batch=16,
    device=0,
    project="runs/my_dataset",
    name="yolo26n",
)
```

运行：

```bash
python train.py
```

初学阶段优先使用 `yolo detect train ...` 命令即可，不需要为了训练而修改 `ultralytics/` 内部源码。

## 第 7 步：理解训练输出

使用上面推荐的 `project` 和 `name` 后，结果目录大致如下：

```text
runs/my_dataset/yolo26n/
├── weights/
│   ├── best.pt
│   └── last.pt
├── args.yaml
├── results.csv
├── results.png
├── confusion_matrix.png
├── train_batch0.jpg
└── val_batch0_pred.jpg
```

重点文件：

- `weights/best.pt`：验证集综合表现最好的权重，测试和部署优先使用它。
- `weights/last.pt`：最后一个训练周期的权重，主要用于断点续训。
- `args.yaml`：本次训练使用的所有参数。
- `results.csv` 和 `results.png`：训练损失、Precision、Recall 和 mAP 等指标。
- `confusion_matrix.png`：查看哪些类别容易混淆或漏检。
- `train_batch0.jpg`：检查训练图片和标注框是否正确。
- `val_batch0_pred.jpg`：查看模型在验证数据上的预测。

## 第 8 步：定量评估模型

有独立测试集时，执行：

```bash
yolo detect val \
    model=runs/my_dataset/yolo26n/weights/best.pt \
    data=dataset.yaml \
    split=test
```

如果没有测试集，使用验证集：

```bash
yolo detect val \
    model=runs/my_dataset/yolo26n/weights/best.pt \
    data=dataset.yaml \
    split=val
```

主要指标：

- **Precision**：模型检测出来的目标中，有多少是正确的。Precision 低通常表示误检较多。
- **Recall**：数据中真实存在的目标中，有多少被模型找到。Recall 低通常表示漏检较多。
- **mAP50**：在 IoU=0.50 条件下的平均精度，相对宽松。
- **mAP50-95**：在 IoU 0.50～0.95 多个阈值下的平均精度，更严格，也更能反映定位准确性。

不要只看一个指标。例如安全检测往往更关心漏检，需要重点观察 Recall；如果错误报警成本很高，则需要更关心 Precision。

## 常见问题和处理方法

### 找不到 `dataset.yaml`

报错中如果显示找不到 `dataset.yaml`，先执行：

```bash
pwd
ls -l dataset.yaml
```

如果文件不在当前目录，可以在命令中使用它的绝对路径。

### 找不到图片

检查 `dataset.yaml` 中的 `path`：

```bash
ls /home/zros/EmbodyAI/Yolo_test/datasets/my_dataset/images/train
ls /home/zros/EmbodyAI/Yolo_test/datasets/my_dataset/images/val
```

这两条命令应该能看到图片文件。

### 标签丢失或标签数量为 0

检查目录名是否为 `labels`，图片和标签是否同名：

```text
images/train/example.jpg
labels/train/example.txt
```

不要把标签放在 `images/train/` 中。

### 类别编号超出范围

如果 `dataset.yaml` 只有两个类别，合法编号只有 `0` 和 `1`。标签中出现 `2` 就会超出范围。

### 标注框位置不正确

常见原因是把像素坐标直接写进了 YOLO 标签，或将 `(xmin, ymin, xmax, ymax)` 错当成了
`(x_center, y_center, width, height)`。检查 `train_batch0.jpg` 是发现此类错误最快的方法。

### CUDA 显存不足

首先减小 `batch`：

```text
batch=16 → batch=8 → batch=4 → batch=2
```

如果仍然不足，再减小 `imgsz`，例如从 `640` 改为 `512`，或使用更小的 `yolo26n.pt`。

### Windows 上数据加载报错

将训练命令中的数据加载进程数设为：

```text
workers=0
```

### 训练集效果很好，验证集效果很差

这通常是过拟合、数据量不足、训练集与验证集分布差异大，或标注质量不一致造成的。优先检查和清洗数据，不要立即增大模型。

### 漏检很多

检查：

- 漏检类别在训练数据中是否过少。
- 训练图片中该目标是否经常没有标注。
- 小目标、遮挡、夜间或特殊角度数据是否不足。
- 测试时的置信度阈值是否过高。

### 误检很多

检查：

- 类别定义和标注规则是否统一。
- 是否包含容易被误认的负样本。
- 数据中是否有错误标签。
- 测试时的置信度阈值是否过低。

## 如果想阅读源码，应该按什么顺序看

只训练自己的数据时，不需要修改下面的源码。如果你想理解内部流程，可以按以下顺序阅读：

1. `ultralytics/engine/model.py`：用户调用 `model.train()` 的入口。
2. `ultralytics/models/yolo/detect/train.py`：目标检测专用的 `DetectionTrainer`。
3. `ultralytics/engine/trainer.py`：通用训练循环、优化器、检查点保存等逻辑。
4. `ultralytics/data/dataset.py`：YOLO 数据集和标签加载逻辑。
5. `ultralytics/models/yolo/detect/val.py`：目标检测验证和指标统计。
6. `ultralytics/models/yolo/detect/predict.py`：预测和后处理。
7. `ultralytics/cfg/default.yaml`：训练、验证和预测参数的默认值。
8. `ultralytics/cfg/models/26/yolo26.yaml`：YOLO26 目标检测模型结构。
